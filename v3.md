# RegimeLab — Workspace Domain & Scope Implementation Specification

## Astra Uygulama Talimatı

Bu doküman, RegimeLab içindeki mevcut **Workspace selector** davranışını düzeltmek ve Workspace kavramını gerçek bir **first-class domain entity** haline getirmek için hazırlanmıştır.

> **Temel problem:** Mevcut Workspace selector yalnızca ekrandaki workspace adını değiştiriyor. Bu davranış yeterli değildir. Workspace değiştiğinde uygulamanın tüm araştırma bağlamı değişmelidir.

Bu çalışma mevcut deney, GA, REST, MCP, sealed-test, research budget ve experiment registry mimarisini bozmadan uygulanmalıdır.

---

# 1. Hedef

Workspace şu anlamı taşımalıdır:

> **Bir research project / research environment / isolated research scope**

Her Workspace kendi:

- Experiments
- Dataset Snapshots
- Search Spaces
- Research Budgets
- Test Seals
- Feature Intelligence
- Experiment Lineage
- Agent Runs
- Jobs
- Artifacts
- Model / Strategy research context

verilerini kapsamalıdır.

Workspace seçmek yalnızca UI label değiştirmemelidir.

---

# 2. Beklenen Domain Model

```text
Workspace
   │
   ├── Experiments
   ├── Dataset Snapshots
   ├── SearchSpaceDefinitions
   ├── ResearchBudgets
   ├── TestSeals
   ├── ExperimentEdges / Lineage
   ├── AgentRuns
   ├── Jobs
   └── Artifacts
```

Temel ilişki:

```text
Workspace
   1
   │
   ├──── N Experiments
   ├──── N Dataset Snapshots
   ├──── N Search Spaces
   ├──── N Research Budgets
   ├──── N Test Seals
   ├──── N Agent Runs
   └──── N Jobs
```

Candidate gibi bazı alt varlıklara doğrudan `workspace_id` vermek zorunlu değildir.

Örneğin:

```text
Candidate
   ↓
Experiment
   ↓
Workspace
```

ilişkisi üzerinden workspace bulunabilir.

Ancak performans gerekirse kontrollü denormalization yapılabilir.

# 3. Workspace Entity

Yeni tablo:

```text
workspaces
```

Önerilen alanlar:

```text
id UUID PK
workspace_code VARCHAR UNIQUE
name VARCHAR NOT NULL
description TEXT NULL

market VARCHAR NULL
base_currency VARCHAR NULL
default_timezone VARCHAR NULL

owner_id UUID NULL
tenant_id UUID NULL

is_archived BOOLEAN DEFAULT FALSE

created_at TIMESTAMP
updated_at TIMESTAMP
archived_at TIMESTAMP NULL
```

Örnek:

```text
workspace_code = WS-FX-001
name           = FX Research
market         = FX
base_currency  = USD
timezone       = UTC
```

# 4. İlgili Tablolara Workspace Scope

Aşağıdaki ana entity'lere `workspace_id` eklenmelidir.



Ancak workspace ilişkisi parent entity üzerinden kesin biçimde bulunabiliyorsa duplicate field eklemek zorunlu değildir.

# 15. Backend Workspace Guard

Backend sadece frontend filtresine güvenmemelidir.

Örnek:

```text
GET experiment EXP-207
```

işleminde:

```text
experiment.workspace_id == current workspace
```

kontrol edilmelidir.

Aksi durumda:

```http
403 Forbidden
```

veya domain tercihine göre:

```http
404 Not Found
```

dönülmelidir.

Tenant isolation varsa:

```text
tenant
   ↓
workspace
   ↓
experiment
```

sırası korunmalıdır.

- [x] `workspaces` gerçek DB entity'si mevcut.
- [x] Mevcut veriler default workspace'e migrate edildi.
- [x] Workspace selector backend datasını kullanıyor. (`GET /workspaces`, sayaçlı liste)
- [x] Selector yalnızca label değiştirmiyor. (switch → scope değişir, listeler yeniden yüklenir)

- [x] Workspace değişince datasets değişiyor. (platform snapshot'ları scope'lu; legacy CSV listesi global kalır)
- [x] Workspace değişince search spaces değişiyor. (API filtresi + cross-workspace kullanımı 404)
- [x] Workspace değişince research budget değişiyor. (workspace başına bütçe satırı, `?workspace_id=`/`X-Workspace-Id` kapsaması, limit PATCH; legacy `global` defter default WS'ye devredilir)
- [x] Workspace değişince sealed test context değişiyor. (seal'ler snapshot üzerinden kapsanır; epoch/invalidate/rotate + history API'de)
- [ ] Workspace değişince lineage context değişiyor. (clone aynı workspace'te kalır; lineage grafiği UI'ı yok)
- [ ] Workspace değişince jobs/agent activity değişiyor. (agent yok; runs endpoint'leri guard'lı)
- [x] Workspace URL'de tutuluyor. (`?workspace=` query param, refresh-safe)
- [x] Browser refresh workspace'i koruyor. (öncelik: URL > localStorage > default)
- [x] New Workspace DB'de kayıt oluşturuyor. (`POST /workspaces` + MCP + UI formu; oluşturunca otomatik geçilir)
- [x] Workspace archive destekleniyor.
- [x] API workspace scope enforce ediyor. (`?workspace_id=`/`X-Workspace-Id` → contextvar guard, cross-access 404)
- [x] Cross-workspace data leakage engelleniyor. (backend + isolation testleri)
- [x] MCP tools workspace-aware. (list/get/create workspace, workspace filtreli liste; okuma uçları query ile kapsamlanabilir)
- [ ] Agent context workspace-aware.
- [ ] Audit log workspace_id içeriyor. (workspace + experiment create/clone audit detaylarında var; tablo kolonu yok)
- [x] Mevcut experiment akışı bozulmuyor. (18 test geçiyor)

# 40. Astra İçin Direkt Prompt

Aşağıdaki talimatı bu dosyayla birlikte uygula:

> RegimeLab'daki mevcut Workspace selector şu anda yalnızca UI label/name değiştiriyor. Bunu gerçek first-class Workspace domain modeline dönüştür. Workspace DB'de kalıcı bir entity olsun. Mevcut tüm verileri güvenli biçimde default workspace'e migrate et. Workspace değiştiğinde experiments, dataset snapshots, search spaces, feature intelligence, lineage, research budget, test seals, jobs, agent activity ve ilgili tüm research context seçili workspace'e göre filtrelensin. Workspace ID URL'de persist edilsin ve browser refresh sonrası korunsun. New Workspace yalnızca isim değiştirmesin, backend üzerinden gerçek workspace kaydı oluştursun. Tüm REST ve MCP işlemlerini workspace-aware yap. Backend cross-workspace erişimi enforce et; sadece frontend filtresine güvenme. Mevcut çalışan experiment/GA/backtest akışını bozma. Migration, backend API, frontend state/router, MCP context, audit ve testleri birlikte tamamla.
